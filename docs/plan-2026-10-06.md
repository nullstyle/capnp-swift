# capnp-swift: development plan

Status: APPROVED by the owner 2026-10-06 (D1 = A, D2 = A, start M0). D3-D6 keep the picks below until their milestone.
Base: capnp-zig v0.20.0 (`01eaebe`, main `1ee6d18`), Zig 0.17.0, Xcode 27.0, Swift 6.4, macOS 27.0.1.

How this plan was made: 5 research agents read capnp-zig and the local Apple SDKs and built probes. 3 architects wrote plans from different angles (MVP-first, risk-first, Swift-API-first). A judge scored them and merged them; MVP-first won. Then 2 fact checkers tried to refute 30 load-bearing claims (21 held, 9 were corrected below), and a critic listed 25 gaps (all folded in below).

Tags: **[V]** = verified by reading code, reading SDK interface files, or running a probe. **[A]** = assumed; it is a risk with a gate that retires it.

---

## 0. The idea in 6 lines

1. capnp-zig keeps doing what it does well: the RPC state machine (questions, answers, imports, exports, embargo, pipelining, Finish, Release), frame parsing and frame validation.
2. Swift owns every socket, through Network.framework (TCP, TLS, Unix sockets, QUIC).
3. The two talk through a small, new, **sans-IO C ABI** ("sans-IO" = the core never touches a socket; Swift pushes bytes in and pulls frames and events out).
4. Swift apps get typed code from a new generator, `capnpc-swift`, and a pure-Swift message reader/builder.
5. Ship the Zig core as a static XCFramework inside a SwiftPM package.
6. First target: a Swift macOS app that talks to a capnp-zig TCP server, both directions, with caps. Then iOS, Unix sockets, TLS, QUIC.

## 1. Facts this plan stands on

### 1.1 Confirmed [V]

- **The Peer is already sans-IO capable.** `Peer.initDetached` (`src/rpc/peer/mod.zig:924`), `attachTransportBinding` (`:1283`), `handleFrame` (`:4171`), `disableThreadAffinity` (`:867`), `setClock` (`:1002`), `checkDeadlines` (`:2655`), `notifyTransportClosed` (`:4080`). The transport seam is `Binding` (`src/rpc/transport/binding.zig`).
- **Deferred replies work.** A call handler can return without replying and reply later with `sendReturnResults` (`mod.zig:3587`) or `sendReturnException` (`:3606`). HostPeer does this (`src/rpc/integration/host_peer.zig:445-566`).
- **The wasm host ABI is not the base.** It is server-only (no bootstrap/call send, no Return delivery), its simple results path writes an empty cap table (`host_peer.zig:329`), and it uses process globals (128-peer table, spin mutex, `page_allocator`; `src/wasm/capnp_host_abi.zig:44-69`, `:115`). We reuse its *pattern* (queue, never call back, pop/commit) but not its symbols.
- **A detached peer with no binding drops close requests** (`binding.zig:91-95`, `mod.zig:4216-4217`). The shim must attach a binding.
- **Zig 0.17.0 builds the static slices.** aarch64/x86_64-macos, aarch64-ios, aarch64/x86_64-ios-simulator, with no SDK. `xcodebuild -create-xcframework` accepts them. A Swift binary that calls a real capnp-zig peer ran on macOS and in the iOS simulator.
- **iOS needs a std workaround and a capnp-zig fix.** Zig 0.17.0 std fails iOS builds at `lib/std/Io/Threaded.zig:15486` (iOS `NullFile` has no fd). It is reached through the default panic handler / `debug_io`, and through capnp-zig `fd_closer.zig:285` `syncIo()`. Fix: root overrides (trap panic, no-op `logFn`, `std_options_debug_io = std.Io.failing`) plus changing `isDarwin()` to `.macos` at `fd_passing.zig:15`, `fd_closer.zig:146`, `fd_budget.zig:68` (the three must agree for the comptime assert at `peer_fds.zig:101`).
- **Link rules.** Do not bundle compiler-rt (`-fcompiler-rt` rebinds the app's `memcpy`/`memset` to Zig's). Do not ship the JSON demo exports (they pull f128 builtins libSystem lacks). Use `-fno-stack-check` for x86_64 Debug slices. A dynamic Swift framework re-exports the Zig C symbols, so ship static. A SwiftPM build-tool plugin cannot hand a `.a` to the linker.
- **Network.framework cannot pass fds.** No SCM_RIGHTS, no peer credentials. Raw `sendmsg`/`recvmsg` from Swift 6 works.
- **Network.framework objects are Sendable** from macOS 14 / iOS 17 (`NWConnection`, `NWListener`, `NWConnectionGroup`). `Synchronization.Mutex` needs macOS 15 / iOS 18.
- **QUIC baseline wire (capnp-zig side).** ALPN `capnp-rpc/1`, client bidirectional stream 0, u32 little-endian length prefix per message, other streams reset with `0x434e5002`, 30 s idle timeout, no PINGs. `src/rpc/transport/quic/length_framer.zig` imports only `std` and `wire/read_cursor.zig`.
- **QUIC on the Swift side.** With the macOS/iOS 26 `NetworkConnection<QUIC>`, the first `openStream()` is stream 0 and ALPN `capnp-rpc/1` negotiates. With the legacy `NWConnectionGroup`, the first stream is 4, so it cannot talk to capnp-zig baseline mode.
- **Network.framework hides QUIC Retry, NEW_TOKEN, stateless reset and connection-ID control.** TLS 0-RTT was never accepted on loopback.
- **e2e harness.** `tools/e2e_self.zig` pairs any server and client binary over `--transport=tcp|unix` and scores TAP output. CLI contract: `tests/e2e/zig/main_server.zig:1958-1965`. There is no QUIC e2e lane and no standalone QUIC e2e binary.
- **Codegen base.** `request` and `schema` are Stable (`docs/api-snapshot.txt:804-805`). `type_resolver` is not exported from `src/lib.zig`.
- **Thread affinity.** Peer panics in Debug when called from a thread other than its creator unless `disableThreadAffinity` is called (`state.zig:240-255`). Swift actors may resume on different threads.
- **EAGAIN hazard.** Non-blocking fds used with `Io.Threaded` can panic on EAGAIN (the capnp-zig wake-door contract). Zig must never do syscalls on Swift-owned fds.
- **The released package has no test assets.** `build.zig.zon` `.paths` holds only `build.zig`, `build.zig.zon`, `build`, `src`, `README.md`, `LICENSE` (`build.zig.zon:78-85`). `tools/`, `tests/` and `vendor/` are not in the hash-pinned package.

**Effects** (one in flight; payload borrowed until `commit`):
- `OUT_FRAME {bytes}`; `CLOSE_REQUESTED`.
- `RETURN {qid, RESULTS | EXCEPTION | CANCELED | DISCONNECTED, msg, caps[], exc_type, reason}`. Exactly one per qid, including the `deinit_ctx`-only paths.
- `INBOUND_CALL {answer_id, export_id, host_tag, iface, method, msg, caps[]}`.
- `ANSWER_FINISHED {answer_id}`: best effort until H5 lands.
- `EXPORT_DROPPED {export_id, host_tag}`: released to zero, or connection torn down. Never for the bootstrap export.
- `EVENT`: plain fields copied from `events.Event` (error name from `@errorName`, static; `events.zig:222-233`).
- `msg` is a standalone message whose root is the params/results struct; its cap pointers index `caps[]` (D5).

### 4.1 Core rules

- **Ownership.** Inputs are borrowed for the call. Effect payloads are borrowed until `commit`; a second `next_effect` before `commit` returns `CAPNP_E_BUSY`. Each effect payload has its own allocation (stable address until its commit). Import caps in effects belong to Swift until `capnp_release`.
- **Threading.** No mutable globals. One caller at a time per connection, any thread. The core never calls into Swift, except the panic hook. Zig handlers run re-entrantly inside `handleFrame` (`mod.zig:517-524`), so they only queue. A debug-only atomic "in call" flag traps on re-entry from Swift.
- **Errors.** `CAPNP_E_{INVAL, BAD_ID, BUSY, CLOSED, LIMIT, PROTOCOL, NOMEM}`. Remote exceptions are data in effects, not errors. A protocol error yields an Abort `OUT_FRAME` then `CLOSE_REQUESTED`. **Every `handleFrame` error is fatal** (M0 decision): decode/validation failures carry the Peer's own Abort; framing and dispatch errors (e.g. `DuplicateQuestionId`) get the shim's Abort. This matches the C++ reference; capnp-zig's own TCP transport treats dispatch errors as non-fatal (`tcp/connection.zig:945-956`). **The one exception is an orderly remote Abort** (M0 review): it is a close, not a protocol failure. The shim sends no Abort back; `push_bytes` returns `CAPNP_E_CLOSED`; `CLOSE_REQUESTED` is queued; `take_error` reports `RemoteAbort` with the remote's reason (stored up to `max_remote_abort_reason_bytes`); and every question still open ends with `RETURN{DISCONNECTED}` carrying that reason once the host reports the transport closed. Zig→C error map: `Busy`→BUSY; `Closed`→CLOSED; `BadId`/`BadCapId`/`CapIndexOutOfRange`→BAD_ID; `Protocol`→PROTOCOL; `Unsupported`/`UnsupportedCapKind`/`Invalid`→INVAL; `OutOfMemory`→NOMEM.
- **Teardown contract.** `conn_free` order: `peer.deinit()` runs while the shim's callbacks write into a discard sink; then the queue is freed. During free the core produces no effects. Swift then resumes every pending continuation with `.disconnected(.closed)` and drops every `host_tag` in its own registry.
- **Transport close ends every question** (M0 review). `transport_closed` queues one `RETURN{DISCONNECTED}` for every open question before it returns. The Peer's own cancel pass can skip questions under OOM (H8), so the shim keeps a list of open questions and sweeps the leftovers from the `RETURN` node each reserved at send time; a later Peer callback for a swept question only frees its context.
- **Bounded inbound copies** (M0 review). The remote controls payload content, and Cap'n Proto pointers may alias, so a small frame can name one blob thousands of times; the Peer's 8 Mi-word traversal limit charges readers for that, but a copy pays for every alias. `INBOUND_CALL` and `RETURN` payloads are therefore never larger than the frame they came in (a tree without aliasing never is), and the clone's working memory is capped at 4x the frame plus 4 KiB (`cap_remap.cloneMemoryLimit`). Aliased params refuse the call (the caller gets an exception named `PayloadCopyExceedsFrame`; no `INBOUND_CALL`); aliased results end the question with `RETURN{EXCEPTION}` (`conn.oversized_results_reason`).
- **Counters saturate.** Diagnostic counters (`Conn.Stats`) are u64 and use saturating adds: bookkeeping never traps a long-lived connection.
- **Pipelining vs Finish.** All Swift calls use `.retained`, so the core never sends Finish on its own. This removes the race where Swift pipelines on a qid the core already finished. Size `max_retained_questions` (default 1024) to the app's in-flight limit.
- **Bootstrap is the exception (M0 finding).** `sendBootstrap` has no options variant, so the bootstrap question is never retained: the Peer sends its Finish itself after the Return. Swift never calls `capnp_finish` on a bootstrap qid, and does not pipeline on it after its `RETURN` (that would race the Peer's Finish); it uses the returned import instead. A small upstream follow-up (a retained bootstrap) can remove this.
- **Deadline cancel ends the record.** A question cancelled by a call deadline (`tick`) gives up its retained record: a later `capnp_finish` on it returns `CAPNP_E_BAD_ID`, which Swift ignores (as after `capnp_cancel`).
- **Versioning.** Option and effect structs start with `struct_size`. Swift checks the ABI version and feature bits at connect.

## 5. Swift API

```swift
let conn = try await RPCConnection.connect(to: .tcp(host: h, port: p), timeout: .seconds(10))
let calc = try await conn.bootstrap(Calculator.self)             // Calculator.Client: Sendable
let n = try await calc.evaluate { $0.expression.literal = 123 }.value.read().value   // pipelined
try await RPCListener(on: .tcp(port: 7000), bootstrap: { CalculatorImpl() }).run()
```

- **Connection actor.** `RPCConnection` is an actor whose `unownedExecutor` is a `DispatchSerialQueue`; the same queue goes to `NWConnection.start(queue:)` [A: M0 probe].
- **Drain loop.** A non-async function (`assumeIsolated` + debug assert). It drains effects after every push, tick or call. `OUT_FRAME`s go to `send` in order.
- **Backpressure, inbound.** Track in-flight inbound handlers (count and bytes). Stop issuing `receive` above a high-water mark (default 64 calls or 8 MiB). Core limit `max_active_inbound_questions` = 4096 (`state.zig:20`) stays as the hard cap.
- **Backpressure, outbound.** Count `OUT_FRAME` bytes between `send` and its completion. Above a high-water mark, `call` suspends on a continuation that send completions resume.
- **Call ordering (E-order).** Calls on one capability must start in arrival order. Start each handler with `Task.immediate` (SE-0472, Swift 6.4) on the connection actor, or feed a per-export FIFO `AsyncStream` drained by one Task. Generated `Server` docs say: handlers start in order and may interleave after their first suspension.
- **Cancellation.** Per-call state machine on the actor: pending-send → sent(qid) → done. `onCancel` hops with `Task { await conn.cancel(token) }`. Cancel before send skips the send. Cancel after `RETURN` ignores `CAPNP_E_BAD_ID`; so does `finish` after a deadline cancel. Never `finish` a bootstrap qid (§4.1). `ANSWER_FINISHED` cancels the handler Task.
- **Releases.** `CapRef.deinit` appends to a `Mutex`-guarded release list; the actor drains it. Dropping the last `RemotePromise` for a qid sends `capnp_finish`.
- **Errors.** `RPCError`: `.failed(publicReason:)`, `.overloaded`, `.disconnected(cause)`, `.unimplemented`, `.canceled`, `.core`. When a Swift handler throws anything else, the remote gets only a generic reason plus a correlation id; the full error goes to `os.Logger`.
- **Events.** `conn.events` is an `AsyncStream`; switches need `@unknown default` (`events.zig:56,95,191`).
- **Streaming methods** (`-> stream`): generated as `async throws` functions that suspend on a Swift-side window (64 calls / 1 MiB by default, matching capnp-zig `docs/streaming.md`). The `StreamResult` return frees window space. The first failure is sticky.
- **Connect and liveness.** `connect(timeout:)` treats `.waiting` as retriable until the timeout, then `.disconnected(.unreachable)`. TCP keepalive on (`NWProtocolTCP.Options.enableKeepalive`, idle/interval/count, `connectionTimeout`). `RPCListener` has `maxConnections`, `firstFrameTimeout`, `idleTimeout`. Opt-in `ReconnectingClient<T>` with backoff and jitter re-bootstraps after a drop.
- **Clock.** `DispatchTime.now().uptimeNanoseconds` (does not advance during sleep). `capnp_conn_new` takes it too, so the Bootstrap sent at once after connect is timed from creation (a clock that read 0 until the first tick let that tick expire it at once; M0 review). Fixed tick interval in v1 (no next-deadline output exists; `checkDeadlines` returns `usize`).
- **iOS lifecycle.** Opt-in `RPCLifecyclePolicy`: on background → `beginBackgroundTask`, `capnp_conn_shutdown` with a short drain, close with `.suspended`; on foreground → reconnect policy.

## 6. Serialization and codegen: option Y

**Choice: a pure-Swift reader/builder, generated by `capnpc-swift`.** Zig is used only for RPC.

Why Y and not the others [V]:
- **X (Zig accessors through C):** every app's schema would be compiled into the Zig binary, so every app build would need Zig; each call bounces Swift↔Zig callbacks (`Peer.sendCall` build callback); ≥0.75 ns per trivial read, and no inlining.
- **Z (opaque bytes + reflection/JSON):** no generic JSON exists, capabilities cannot be represented, no typed params/results.
- **Y:** readers are Swift values (Sendable), inlinable, no FFI ownership. Cost today ~1.5-1.8 ns per u32 read with a span opened per access; ~0.25-0.30 ns once `Lifetimes` is stable. The `Capnp` product can later ship without the XCFramework (D3 b).

**Runtime rules.**
- Readers hold owned storage (struct around the bytes) and open a `RawSpan` per access. Generated code never indexes `Data`.
- Bounds-checked loads everywhere. A wrong pointer kind or a short struct returns the default (validation is structural only).
- Text is read strictly (`message.zig:164-176`).
- Effect payloads were already validated by Zig. Standalone untrusted bytes go through `capnp_message_validate` (D3).
- **Forward compatible by rule:** enums are generated as `RawRepresentable` structs with static members (or with an `.unknown(UInt16)` case); every `which()` has `.unknownDiscriminant(UInt16)`. No force unwraps in generated code (lint: `grep -n '!' Generated/` with an allowlist).

**capnpc-swift.**
- Written in Zig on the Stable `request` and `schema` modules (`api-snapshot.txt:804-805`). Generics are erased to `AnyPointer` in v1 (`type_resolver` is not exported; H7).
- Emits: Readers, Builders, `Client` stubs, `Server` protocols, `RemotePromise` pipelining extensions, `stream` method wrappers. Escapes Swift keywords.
- **Multi-file schemas:** one Swift file per schema file; imports dependency modules. A `swift.capnp` annotation file (new file ID) with `$Swift.module` and `$Swift.prefix`.
- **Schema compiler for users:** capnp-zig's toolchain needs Python/uv + Wasmtime (`docs/capnp-wasm-toolchain.md`); users will not have that. Ship the compiler inside the `capnpc-swift.artifactbundle` (D6).
- **Delivery:** a command plugin first (`swift package --allow-writing-to-package-directory capnp-generate`, plus `--check` in CI; generated code is committed). A build-tool plugin only after a probe shows the compiler runs in the SwiftPM sandbox.

## 7. Transports, in order

1. **TCP** (Stable on the capnp-zig side).
   - Swift: `NWConnection` / `NWListener`, `.tcp`, `noDelay`, keepalive. Raw `receive(minimumIncompleteLength: 1, maximumLength: 65536)` feeds `push_bytes`.
   - Interop: standard segment-table framing; no preamble, no TLS, no heartbeat. Either side may send first. Keep outbound frames ≤511 segments (C++ limit). A Swift server sets its own first-frame timeout.
2. **Unix sockets.**
   - Swift: `NWEndpoint.unix(path:)`. Reject paths over 104 bytes before any NW call. After listener `.ready`, check the socket file exists. Bind inside a 0700 directory and `flock` `<path>.lock` (capnp-zig's convention, `docs/rpc-unix-sockets.md`).
   - capnp-zig peers must keep `max_fds_per_message = 0` toward NW peers (`rpc-unix-sockets.md:216-247`).
3. **TLS over TCP.** Swift↔Swift only (capnp-zig TCP has no TLS). `sec_identity_t` is not Sendable: build the identity inside the queue closure. Test identity via `SecPKCS12Import`.
4. **QUIC baseline** (`@available(macOS 26, iOS 26)`; **Experimental** in capnp-swift because it is Experimental in capnp-zig, `docs/stability.md:31`).
   - Swift: `NetworkConnection<QUIC>`; first `openStream()` = stream 0. Never `NWConnectionGroup` (starts at 4).
   - ALPN and codes read from the core (`capnp_core_quic_alpn()`). `framing = U32_LE`. Keepalive under 30 s. A Swift server resets other streams with `0x434e5002`. Map close codes `0x434e5001`-`0x434e5004`.
   - TLS trust: a pinned-CA option for production and an explicit test-only "trust this cert" option; never a silent skip-verify.
   - Not available through Network.framework: 0-RTT acceptance, Retry/NEW_TOKEN, stateless reset, CID control (non-goals).
5. **FD passing** (post-0.1, macOS only, D4). A raw `AF_UNIX` socket owned by Swift (DispatchSource), `sendmsg`/`recvmsg` in Swift, fds handed to the core through `push_bytes_fds`. Zig never does syscalls on Swift fds.
6. **WebSocket:** non-goal for v1. Later option: `framing = MESSAGE` (one frame per push) + `NWProtocolWebSocket`, tested against the C++ reference.

## 9. Testing and CI

- **Runners:** macOS arm64, Xcode 27, Zig from mise.
- **Lanes:** `swift test` debug + release; TSan; ASan; iOS simulator; iOS device build; `xcframework` + `check-symbols`; interop (Zig peers built from the pinned checkout); `capnp-generate --check`; `core` `zig build test test-abi`.
- **Fuzz:** 5 min per change; 30 min nightly.
- **Drift:** nightly build of `core/` against capnp-zig `main` (read-only fetch), until the shim moves upstream. The sans-IO surface is Experimental in capnp-zig (`api-snapshot-experimental.txt:1958, 2023, 2069, 2081, 2257`).
- **Sanitizers:** TSan/ASan instrument only Swift. Zig is covered by ReleaseSafe checks [A].
- **Ablation:** every new gate test is broken once on purpose to prove it can fail (capnp-zig's dead-test lesson).

## 10. Packaging and release

- **Format:** static `CapnpCore.xcframework`, ReleaseSafe. Text is ~556-653 KB per slice [V].
- **Do not:** bundle compiler-rt; ship a dynamic product; ship the JSON demo exports.
- **Debug info:** do **not** strip the static slices (an app's dSYM is built from the DWARF inside the `.a`; a separate dSYM for a static library does not work). Debug prefix mapping is **not possible at Zig 0.17.0** (no `-fdebug-prefix-map`; M0 finding), so the slices' DWARF holds the absolute build paths. M7 decides how release slices avoid leaking local paths (e.g. build from a neutral checkout path).
- **Version pin:** each capnp-swift release pins one capnp-zig hash and reports it in `capnp_core_version()`.
- **Platform floor:** macOS 15 / iOS 18 (Zig's default minimum and `Synchronization.Mutex`); QUIC needs 26. `platforms:` lists only what ships.
- **Privacy:** `PrivacyInfo.xcprivacy` in `CapnpRPC` and the XCFramework.
- **Signing:** `codesign --timestamp -s <identity>` on the XCFramework; the owner holds the identity.
- **Release ceremony (`docs/release.md`):** (1) build the XCFramework + artifactbundle from a candidate commit; (2) `swift package compute-checksum`; (3) commit `Package.swift` with url + checksum; (4) rebuild from that commit and require identical inner `.a` checksums; (5) **owner approves the tag and the asset upload**; (6) post-publish: a fresh consumer package resolves the URL and builds.
