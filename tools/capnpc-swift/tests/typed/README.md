# Opt-in typed generator fixtures

These are synthetic schemas owned by this repository. `--typed` adds open Swift
schema applications to the existing generated namespaces; these tests do not use
a finite specialization profile. The ordinary generator goldens remain in
`../golden`.

Run from the repository root:

```sh
mise exec -- just typed-structs
mise exec -- just typed-rpc
mise exec -- just typed-driver
mise exec -- just typed-rpc-cpp
```

`check.sh` also accepts a prebuilt generator as its only argument. It builds the
pure Swift `Capnp` module in an isolated temporary directory and verifies:

- Open Text, Data, list, struct, recursive, changing recursive, and nested
  lexical applications, including an application absent from the schema's roots.
- Reader ownership, Builder lifetime, erased interoperability, generic groups,
  scalar/enum/list defaults, unknown enum values, and union setters/initializers.
- Separate Swift modules, two same-name declarations generated in both request
  orders, and a consumer importing only one declaration from a colliding module.
- A wrong generic binding rejected by Swift and duplicate requested files
  rejected before the generator writes any source file.

There are 32 distinct named checks in the struct/CLI gate. Repeating a collision
check against the opposite producer order exercises the same check again.

`check-rpc.sh` uses the immutable macOS core archive and real loopback transports.
It regenerates and compares the two Swift fixtures in `generated/`; use
`check-rpc.sh --update` when deliberately updating those expected sources.
`check-rpc-cpp.sh` builds an independent C++ peer and checks Swift/C++ calls in
both directions. `check-driver.sh` exercises the compiler host's public `--typed`
generate and check path.

`check-legacy-rpc.sh` checks ordinary generation without `--typed`. Its synthetic
`legacy_reserved` fixture inherits interfaces named `Target` and `Connection`,
then calls both ancestor views over real loopback transports. It compares
`generated/legacy_reserved.swift`; `--update` regenerates that expected source.

`check-legacy-defaults.sh` verifies ordinary struct and list defaults against the
vendor schema's explicit values and its compiler-produced message fixture. Its
11 named checks cover nested struct pointers, supported list element kinds,
nonfinite float values, nested lists, explicit null, and explicit wire overrides.
`--update` regenerates the Widget golden, vendor bindings, and the synthetic
`legacy_list_defaults` golden.

`check-legacy-void.sh` verifies the `VoidListReader` and `VoidListBuilder` APIs:
compiler-produced defaults, element-free storage, explicit empty overrides,
null and wrong-kind pointers, and malformed offsets. Its six runtime checks
and generated API compile guard use the same synthetic list fixture.

`check-empty-composite.sh` verifies that empty struct lists override nonempty
defaults in legacy and typed builders, survive owned copying, and pass actual
CALL/RETURN traffic through the released core. It covers both nonzero and zero
element layouts. When native `capnp` is installed it also reproduces the C++
fixture and decodes Swift output; `--require-cpp` makes that live oracle mandatory.

## Request provenance and reproduction

Every `.request.bin` here was generated by the repository's pinned `capnp.wasm`
through `capnpc-driver` and WasmKit, with `/bin/cat` as the plugin. The compiler's
SHA-256 is
`5429b7277b18b6e3f65430068ac41ac327ef8dd359603955f16ec576e0c3a14a`.
The new requests were regenerated a second time and compared byte for byte.

To regenerate the complete set, first build the driver with
`mise exec -- just driver-build`, then run this Bash block from the repository
root. Preserve argument order: the `ab` and `ba` requests intentionally reverse
it, and the duplicate request intentionally supplies one file twice.

```bash
fixture_dir=tools/capnpc-swift/tests/typed
request() {
  request_name=$1
  shift
  request_sources=()
  for source in "$@"; do
    request_sources+=("$fixture_dir/$source.capnp")
  done
  .build/debug/capnpc-driver --plugin /bin/cat \
    --wasm tools/capnpc-swift/wasm/capnp.wasm \
    --include tools/capnpc-swift --src-prefix "$fixture_dir" \
    "${request_sources[@]}" > "$fixture_dir/$request_name.request.bin"
}
request open_structs open_structs
request external external
request consumer consumer
request collision_ab collision_a collision_b
request collision_ba collision_b collision_a
request producer_ab producer_a producer_b
request producer_ba producer_b producer_a
request consumer_collision consumer_collision
request duplicate open_structs open_structs
request open_rpc_inheritance open_rpc_inheritance
request open_rpc_conflict open_rpc_conflict
request legacy_reserved legacy_reserved
request legacy_list_defaults legacy_list_defaults
request empty_composite empty_composite
```

`empty_composite.cpp.bin` is an independent C++ 1.5.0 encoding of this
repository's synthetic schema, with SHA-256
`965a2f1c3a1c068ac4761c0bf3143c9885ba708c566a891fe49b7988c3d99750`.
Reproduce it with:

```sh
printf '(items = [], zeros = [])\n' | capnp encode \
  tools/capnpc-swift/tests/typed/empty_composite.capnp EmptyContainer \
  > tools/capnpc-swift/tests/typed/empty_composite.cpp.bin
```

`OpenApplicationsMain.swift` and the RPC peer additionally use the synthetic
requests in `tools/type-resolver-spike/fixtures`; their provenance is recorded in
that directory. Stable `Node<id>` aliases are the generated cross-module
contract, while `Box.Typed<T>` remains the convenient public facade.

Typed streaming methods and conflicting inherited applications of the same
interface are explicitly rejected before source output. Ordinary generation
retains its existing behavior for those schemas.
